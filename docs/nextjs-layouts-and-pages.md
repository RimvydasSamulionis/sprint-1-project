# Next.js App Router — Layouts and Pages

Source: https://nextjs.org/docs/app/getting-started/layouts-and-pages

---

Next.js uses **file-system based routing** — folders and files define routes.

## Creating a page

A **page** is UI rendered on a specific route. Add a `page.tsx` file inside the `app` directory and default export a React component.

```tsx
// app/page.tsx
export default function Page() {
  return <h1>Hello Next.js!</h1>
}
```

## Creating a layout

A **layout** is UI shared between multiple pages. On navigation, layouts preserve state and do not re-render. Define one by default exporting a React component from a `layout.tsx` file. It must accept a `children` prop.

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <main>{children}</main>
      </body>
    </html>
  )
}
```

The root layout (`app/layout.tsx`) is **required** and must include `<html>` and `<body>` tags.

## Creating a nested route

- **Folders** map to URL segments.
- **Files** (`page.tsx`, `layout.tsx`) create the UI for that segment.

Nest folders to nest routes:

```
app/
  blog/
    page.tsx        →  /blog
    [slug]/
      page.tsx      →  /blog/:slug
```

## Nesting layouts

Add a `layout.tsx` inside a route folder to wrap only that route and its children:

```tsx
// app/blog/layout.tsx
export default function BlogLayout({ children }: { children: React.ReactNode }) {
  return <section>{children}</section>
}
```

The root layout wraps the blog layout, which wraps the blog page and all blog post pages.

## Dynamic segments

Wrap a folder name in square brackets to create a dynamic segment:

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPostPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)
  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}
```

## Search params

Access search parameters in a Server Component page via the `searchParams` prop:

```tsx
// app/page.tsx
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = (await searchParams).filters
}
```

In Client Components, use the `useSearchParams()` hook instead.

**When to use each:**
- `searchParams` prop — when you need params to load data (pagination, DB filtering)
- `useSearchParams()` hook — when params are only used client-side (filtering already-loaded data)

## Linking between pages

Use the `<Link>` component from `next/link` for client-side navigation with prefetching:

```tsx
import Link from 'next/link'

export default function PostList({ posts }) {
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
```

For advanced navigation, use the `useRouter` hook.

## TypeScript helpers

`PageProps` and `LayoutProps` are globally available utility types (generated by `next dev` / `next build`):

```tsx
// app/blog/[slug]/page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  return <h1>Blog post: {slug}</h1>
}
```

```tsx
// app/dashboard/layout.tsx
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return <section>{props.children}</section>
}
```

No imports needed — these types are globally available.
